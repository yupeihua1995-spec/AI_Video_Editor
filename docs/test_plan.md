# 在线AI Native视频编辑器 测试计划文档

## 1. 测试目标

本测试计划旨在确保“在线AI Native视频编辑器”的各项功能（包括基于Chat的AI交互、代码沙盒动态生成与容错、基于Remotion的逻辑物理裁剪以及Serverless视频渲染）的稳定性、正确性和高性能。由于项目集成了大语言模型（MLLM）实时生成代码并在前端执行，**代码隔离沙盒的稳定性和失败回退（Fallback）机制**将是测试的重中之重。

---

## 2. 测试范围划分

### 2.1 单元测试 (Unit Testing)
**目标**：验证核心函数和独立组件的正确性。
**工具**：Jest / Vitest, React Testing Library
**测试重点**：
1.  **Remotion组件**：针对基础内置的Remotion组件（如特定的文字动画、滤镜组件）进行Props传递和渲染输出的快照测试。
2.  **数据转换工具**：
    *   ASR结果解析函数（测试正确提取水词时间戳）。
    *   时间轴重计算函数（输入原始时间与水词列表，输出裁剪后的 `<Sequence>` 起止时间列表，确保数学逻辑100%正确）。
3.  **状态管理 (Zustand/Redux)**：测试视频时间轴状态更新、沙盒代码版本的提交与回退逻辑。

### 2.2 接口与集成测试 (Integration Testing)
**目标**：验证前后端交互、第三方API（ASR/MLLM）集成、以及前端沙盒的编译流程。
**工具**：Postman / Newman, Playwright (组件/沙盒级集成测试)
**测试重点**：
1.  **WebSocket通信**：
    *   长连接的建立、心跳维持、断线重连（如网络抖动时的表现）。
    *   流式JSON数据解析，确保前端能正确拼装完整的代码字符串而不截断。
2.  **前端沙盒 (WebContainers/Sandpack)**：
    *   **代码注入与编译**：输入预期的正常React/Remotion代码，验证沙盒能否在预期时间内（如<2秒）完成编译并触发HMR热更新。
    *   **跨域资源加载**：确保沙盒内能正常加载主站资源或跨域的第三方字体、图片资源。
3.  **大语言模型集成**：通过Mock数据或稳定Prompt测试BFF层封装MLLM的接口能力。

### 2.3 异常容错与回退测试 (Fallback & Chaos Testing)
**目标**：专门针对“AI生成代码”的不可控性进行测试。
**测试重点**：
1.  **语法错误**：模拟AI返回了缺少括号或引用的破坏性React代码，验证沙盒的 `Error Boundary` 能否成功捕获。
2.  **运行时崩溃**：模拟代码能编译通过，但执行时出现死循环或渲染报错（如访问未定义属性），验证UI是否被有效隔离（不影响主页面）。
3.  **状态回退验证**：当上述错误发生时，验证系统能否：
    *   自动销毁故障实例。
    *   从版本历史栈中拉取上一个稳定代码重新注入。
    *   向Chat界面发送友好的错误提示反馈给用户。

### 2.4 端到端测试 (E2E Testing)
**目标**：模拟真实用户的主干业务流程。
**工具**：Cypress / Playwright
**测试用例（Happy Path）**：
1.  用户打开编辑器，导入一段本地视频（含语音）。
2.  用户在侧边栏输入：“帮我去掉视频里的废话，并生成中文字幕。”
3.  系统调用ASR -> 识别水词 -> 逻辑层裁剪时间轴 -> 自动添加字幕组件 -> 时间轴与播放器界面更新。
4.  用户继续输入：“在前10秒加一个黑白滤镜”。
5.  WebSocket推送代码 -> 沙盒编译成功 -> 播放器实时展现滤镜效果。
6.  用户点击“导出”。
7.  触发Serverless渲染 -> 返回下载链接。

### 2.5 性能与压力测试 (Performance Testing)
**目标**：评估系统在高并发或复杂计算下的表现。
**工具**：JMeter / k6 / Chrome DevTools
**测试重点**：
1.  **前端性能**：Remotion Player在复杂特效或高频逻辑裁剪下的FPS表现；内存泄露检查（尤其在频繁热更新组件后）。
2.  **Serverless渲染并发限制**：模拟多用户同时提交渲染任务，测试 `@remotion/lambda` 的拉起速度（冷启动延迟）与并发渲染成功率。验证AWS Lambda配额（Concurrency Limits）是否足够。
3.  **WebSocket负载**：测试单个Node.js节点能承载的并发长连接数量，以及大规模流式消息传输时的CPU占用。

---

## 3. 测试环境与阶段规划

1.  **开发自测阶段（Dev/Mock环境）**：采用全Mock模式，断开真实的MLLM与ASR调用，使用固定返回数据验证前后端及沙盒逻辑。
2.  **联调测试阶段（Staging环境）**：接入真实的第三方服务API；验证真实的Serverless渲染链（部署测试版的Remotion Lambda）。
3.  **预发布回归（Pre-Production）**：执行全量的自动化E2E测试脚本；验证Fallback机制的可靠性。
4.  **线上监控（Production）**：部署Sentry进行前端错误捕获；配置AWS CloudWatch/Datadog监控Lambda渲染失败率和WebSocket断连率。
